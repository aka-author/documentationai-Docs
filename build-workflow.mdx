# Windows exe build and installer workflow

This document describes how the Erase & Rewrite Windows binary is produced, how the Inno Setup installer is produced, and the **arguments / interfaces** of each script involved.

## Repository layout (paths the scripts assume)

- <strong>`codebase/`</strong> РІР‚вЂќ Git repository root (contains `win-go/`, `scripts/`, `installer/`, `docs/`).
- <strong>`win-go/`</strong> — Go module; legacy `build.ps1` lives here.
- <strong>`win-cpp-qt/`</strong> — C++ Qt module; **shipping** `build.ps1 -StaticQt` lives here.
- **Project root** РІР‚вЂќ parent of `codebase/` (the script calls it `$ShitwiperRoot`; equivalent to `codebase\..`). Build output goes under <strong>`<ProjectRoot>\bin\win\`</strong>, not under `codebase\` only.
- <strong>`<ProjectRoot>\tools\`</strong> РІР‚вЂќ location for helper tool executables. Tool `.exe` files must not stay in `win-go\`.

So with a clone at `<ProjectRoot>\codebase\`, the exe lands in <strong>`<ProjectRoot>\bin\win\current\`</strong>.

## 1\. Exe build: `win-go/build.ps1`

### Flow direction (important)

- This workflow is **build-driven**: you run the build script, and that build process may create commits.
- It is **not commit-driven**: normal commits must not be treated as a trigger to start builds.
- In short: <strong>build => commit(s)</strong>, not **commit => build**.

### How you run it

```powershell
# From any working directory; paths are derived from the script location.
powershell -NoProfile -ExecutionPolicy Bypass -File "path\to\codebase\win-go\build.ps1"
```

Or `cd` into `win-go` and run `.\build.ps1`.

### Parameters / CLI

<strong>None.</strong> The script does not accept command-line arguments. It always uses:

| Symbol | Meaning |
| --- | --- |
| `$ModuleRoot` | Directory containing `build.ps1` (`win-go/`) |
| `$CodebaseRoot` | Parent of `$ModuleRoot` (`codebase/`) |
| `$ShitwiperRoot` | Parent of `$CodebaseRoot` |
| `$WinBinRoot` | `<ProjectRoot>\bin\win` |
| `$OutDir` | `{WinBinRoot}\current` |
| `$Exe` | `{OutDir}\Erase & Rewrite.exe` |

### High-level steps (in order)

1. Walk parents of `win-go/` to find <strong>`.git`</strong> (`$GitRoot`). If missing, git commits and real branch/commit in history are skipped (warning only).
2. **Bump build** in `win-go/versioninfo.json`: increment numeric `FixedFileInfo.*.Build` only; string `FileVersion` / `ProductVersion` use **four uppercase hex digits** for the fourth segment (e.g. `0.1.0.000A`). Fails if build would exceed `0xFFFF`.
3. Copy or generate **About** PNG into `win-go/assets/art/`; run <strong>`go run ./tools/genicons`</strong>; run <strong>`go generate .`</strong> (includes Windows resource / `goversioninfo`).
4. Move any root-level `win-go\*.exe` helper artifacts to <strong>`<ProjectRoot>\tools\`</strong> (enforced by the build script).
5. If `$GitRoot` exists: <strong>`git add -A`</strong> then <strong>`git commit -m "build: version {productVer}"`</strong> (full-repo snapshot; throws if nothing staged).
6. <strong>`Prepare-CurrentBuildFolder`</strong>: if `bin\win\current` is non-empty: if a <strong>`*.date`</strong> marker exists and `{WinBinRoot}\{markerStem}` does not exist yet, move all items into that archive folder; otherwise clear `current` (details in script comments).
7. <strong>`go build`</strong> РІвЂ вЂ™ `Erase & Rewrite.exe` under `current` (`CGO_ENABLED=0`, `-H windowsgui`, `-trimpath`, `-buildvcs=false`).
8. Optional **Authenticode** if `ERASE_REWRITE_SIGNTOOL` is set (see below).
9. Copy `versioninfo.json` beside the exe; write <strong>`.date`</strong> marker (name + body), <strong>`build-meta.json`</strong>, append <strong>`docs/history/builds.txt`</strong>.
10. If `$GitRoot` exists: <strong>`git add -A`</strong> and <strong>`git commit -m "docs: append build {productVer} to history"`</strong>.

### Environment variables (exe build only)

| Variable | Purpose |
| --- | --- |
| `ERASE_REWRITE_SIGNTOOL` | If set, full path to <strong>`signtool.exe`</strong>; after `go build`, the script runs signing on `Erase & Rewrite.exe`. |
| `ERASE_REWRITE_SIGN_ARGS` | Optional; split on whitespace and passed to `signtool` between `sign` and the exe path. |

## 1b. Exe build: `win-cpp-qt/build.ps1` (shipping static Qt)

The active Windows C++ Qt implementation uses <strong>`win-cpp-qt/build.ps1`</strong>. Shipping builds pass <strong>`-StaticQt`</strong>.

### How you run it

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "path\to\codebase\win-cpp-qt\build.ps1" -StaticQt
```

### Parameters

| Switch | Meaning |
| --- | --- |
| `-StaticQt` | Link Qt and required plugins statically; output one `EraseAndRewrite.exe` (no `windeployqt`). <strong>Required for release.</strong> |

Without `-StaticQt`, the same script builds against the shared Qt kit and runs `deploy-standalone.ps1` for development.

### Output layout

Same as Go: <strong>`<ProjectRoot>\bin\win\current\EraseAndRewrite.exe`</strong> plus `versioninfo.json`, `build-meta.json`, and a `.date` marker. Static mode ships **no** `Qt6*.dll` or plugin folders beside the exe.

### High-level steps (static / `-StaticQt`)

Same git and folder discipline as `win-go/build.ps1` (version bump, snapshot commit, archive prior `current` via `.date`, history commit). Additionally:

1. <strong>`Wipe-BinQtDeployArtifacts`</strong> — remove legacy Qt DLL/plugin trees from all `bin/win/*` folders.
2. <strong>`Sync-ArtAssets`</strong> — copy `art/broombunny*.png` from project root into `codebase/assets/art/` (About dialog art).
3. <strong>`tools/build_app_ico.cpp`</strong> builds `app.ico` and per-size PNGs from `assets/art/broombunny*.png`; <strong>`app.rc`</strong> embeds the icon.
4. CMake configure/build in <strong>`build-static/`</strong> with `-DWTW_STATIC_QT=ON` against `mingw_64_static`.
5. Copy <strong>`EraseAndRewrite.exe`</strong> to `bin/win/current/`.
6. <strong>`Strip-MingwStaticExe`</strong> — `strip --strip-all` via the Qt MinGW toolchain (see below).
7. Write <strong>`versioninfo.json`</strong>, <strong>`build-meta.json`</strong>, and a <strong>`.date`</strong> marker beside the exe (before smoke test, so a failed test still leaves traceable output).
8. <strong>`test-run.ps1 -StaticQt`</strong> — import-table checks and smoke launch (optional verification).

Full detail: [specs/arch-win-cpp-qt.md](/specs/arch-win-cpp-qt) §9, [specs/impl-win-cpp-qt.md](/specs/impl-win-cpp-qt) §13.

### Static executable size and debug overlay stripping

Static MinGW links produce a <strong>~47 MB</strong> file immediately after link, but only <strong>~29 MB</strong> is the functional PE image. The remaining <strong>~20 MB</strong> is a **debug overlay** (DWARF data from static `.a` archives) appended after the last PE section. It is not needed to run the program.

<strong>Shipping policy:</strong> step 6 above runs <strong>`strip --strip-all`</strong> on the copied exe. Typical result: <strong>~28 MB</strong> shipping binary (build **1.0.0.001A** onward).

| Stage | Typical size |
| --- | --- |
| Link output | ~47 MB |
| After `strip --strip-all` | ~28 MB |

This satisfies techspec **WR-03**: standard PE metadata and `VERSIONINFO` (`.rsrc`) are preserved; only debug overlay is removed. `strip --strip-debug` alone is **not** sufficient — it leaves the large tail intact.

Environment overrides: `CMAKE_PREFIX_PATH` (shared kit hint), `QT_STATIC_PREFIX` (explicit static prefix).

Optional signing: same `ERASE_REWRITE_SIGNTOOL` / `ERASE_REWRITE_SIGN_ARGS` variables as the Go build (applied after tests).

## 2\. Installer build: `scripts/build-installer.bat`

Run **after** a successful exe build so `SourceDir` contains `Erase & Rewrite.exe`.

### Arguments (required)

```bat
scripts\build-installer.bat <SourceDir> <OutputRootDir>
```

| Arg | Position | Description |
| --- | --- | --- |
| `SourceDir` | `%1` | Folder that **must** contain <strong>`Erase & Rewrite.exe`</strong> (typically `<ProjectRoot>\bin\win\current`). Expanded with `%~f1`. |
| `OutputRootDir` | `%2` | Root directory under which the batch creates a **timestamped** subfolder and passes that to Inno as output. Expanded with `%~f2`. |

Default project convention: set `OutputRootDir` to <strong>`<ProjectRoot>\delivery\win`</strong> unless explicitly overridden.

The batch resolves <strong>`installer\Erase & Rewrite.iss`</strong> as `"%SCRIPT_DIR%..\installer\Erase & Rewrite.iss"` (i.e. relative to `scripts/`, inside **codebase**).

### Behavior

1. Validates `SourceDir` and `Erase & Rewrite.exe`; creates `OutputRootDir` if missing.
2. Sets `STAMP` to `yyyy-MM-dd_HH-mm` (via PowerShell), then `OUTPUT_DIR = OutputRootDir\STAMP`.
3. Locates **Inno Setup 6** `ISCC.exe`: `%LOCALAPPDATA%\Programs\Inno Setup 6\`, `ProgramFiles(x86)`, `ProgramFiles`, then <strong>`PATH`</strong>.
4. Invokes:

   ```text
   ISCC.exe "/DSourceDir=<SourceDir>" "/DOutputDir=<OUTPUT_DIR>" "<path\to>\installer\Erase & Rewrite.iss"
   ```

### Exit codes (batch)

| Code | Meaning |
| --- | --- |
| 0 | Success |
| 2 | Missing `SourceDir` or `OutputRootDir` |
| 3 | `SourceDir` does not exist |
| 4 | `Erase & Rewrite.exe` missing under `SourceDir` |
| 5РІР‚вЂњ8 | mkdir / stamp failures |
| 6 | `ISCC.exe` not found |
| 9 | Inno script path not found |
| Other | Inno compiler return code |

## 3\. Inno script: `installer/Erase & Rewrite.iss`

This file is **not** run directly; <strong>`ISCC.exe`</strong> compiles it. The batch always passes the defines below.

### Preprocessor defines (compiler `/DРІР‚В¦`)

| Define | Required | Default if omitted | Meaning |
| --- | --- | --- | --- |
| `SourceDir` | **Yes** (script `#error`s if missing) | РІР‚вЂќ | Directory tree packaged into `{app}`; must contain `Erase & Rewrite.exe`. |
| `OutputDir` | No | Falls back to `SourceDir` in the `.iss` | Where the generated **setup .exe** is written. The batch always sets it to `OutputRootDir\yyyy-MM-dd_HH-mm`. |
| `SetupIcon` | No | `..\win-cpp-qt\resources\app.ico` | Broombunny `.ico` for the setup executable (`SetupIconFile`). The batch always passes the built `app.ico` path. |

### Version string

`ProductVersion` is read at compile time from <strong>`GetStringFileInfo(SourceDir + "\Erase & Rewrite.exe", "ProductVersion")`</strong>. If empty, it falls back to `0.0.0.0`. <strong>`OutputBaseFilename`</strong> becomes `Erase & Rewrite-Setup-{#ProductVersion}`.

### Packaging rules (summary)

- <strong>`[Files]`</strong> installs only:

  - `EraseAndRewrite.exe` from `SourceDir` (the build output folder)
  - `COPYING`, `LICENSE-NOTICE`, and `THIRD-PARTY-NOTICES` from `installer/` (LEGALSPEC LS-50)
- Build metadata (`versioninfo.json`, `build-meta.json`, `*.date`) stays in `bin/win/current` for engineering traceability and is **not** shipped to `{app}`.
- **Legal notice page**: `[Setup]` uses `InfoBeforeFile=INSTALL-LICENSE.txt`, so the installer shows GPL and third-party license notices before file installation with **Next** only — no acceptance gate (GPLv3 section 9; LEGALSPEC LS-120).
- **Icons**: `SetupIconFile` uses broombunny `app.ico` (same asset embedded in `EraseAndRewrite.exe`). Start Menu and desktop shortcuts set `IconFilename` to the installed exe and `AppUserModelID` to `MikhailOstrogorskiy.EraseAndRewrite`.

## 4\. End-to-end example (typical machine)

<strong>Qt shipping build (current Windows line):</strong>

```powershell
Set-Location ...\codebase\win-cpp-qt
.\build.ps1 -StaticQt
```

<strong>Go build (legacy reference line):</strong>

```powershell
Set-Location ...\codebase\win-go
.\build.ps1
```

```bat
<ProjectRoot>\codebase\scripts\build-installer.bat "<ProjectRoot>\bin\win\current" "<ProjectRoot>\delivery\win"
```

The installer executable appears under <strong>`<ProjectRoot>\delivery\win\<yyyy-MM-dd_HH-mm>\`</strong>.
